# ZAPRUDA COMMUNITY

**Сообщество о рыбалке — для всех рыболовов.**

ZAPRUDA COMMUNITY — приложение и сообщество для людей, которым интересна рыбалка во всём её разнообразии: спиннинг, поплавок, фидер, донная ловля, нахлыст, зимняя рыбалка, подводная охота и другие направления. Здесь можно общаться с рыболовами рядом, планировать совместные выезды, делиться отчётами и уловами, обсуждать снасти и водоёмы.

**Важно:** ZAPRUDA — **не только** спиннинговое сообщество. Street fishing и спиннинг отражают интересы первых участников, но не ограничивают другие виды рыбалки, опыт или возраст пользователей.

## Версия и статус

- **Текущий кандидат:** `v0.7.5 SPOT`, подготовка закрытого пилота, **не публичный релиз**.
- **Интеграция:** [PR #93](https://github.com/SergeyGalkin91/zapruda1/pull/93) → `release/v0.7.5-spot`. Точный SHA и результаты проверок определяются по GitHub, а не по статическому тексту README.
- **Основная ветка `main`:** пока содержит прежнюю выпущенную/базовую кодовую линию и **не обновлена** до кандидата v0.7.5.
- **Тестовая база:** отдельный Supabase STAGING. Изменения STAGING не означают обновление production.
- **Размещение для тестов:** рассматривается **только Netlify**; подтверждённый живой URL и SHA STAGING-деплоя должны быть установлены отдельно. Не считать обычный CI доказательством публикации сайта.

**Публичный запуск — NO-GO**, пока не завершены реальные проверки JWT, браузерной сборки, приватности, необходимых зависимостей и релизные разрешения. Не путать реализацию функции с её полной приёмкой.

## Для чего создаётся ZAPRUDA

- **Лента:** рыболовные отчёты, уловы, фотографии, реакции и обсуждения.
- **Комьюнити:** общение по интересам и городам, поиск единомышленников и напарников.
- **Чаты:** тематические и географические беседы; безопасность доступа и фотографий проверяется отдельно.
- **Выезды и СХОДКИ:** планирование совместной рыбалки; СХОДКИ задуманы бесплатными.
- **Профиль рыболова:** снасти, комплекты, активность, достижения и личные настройки.
- **SPOT и водоёмы:** работа с рыболовными местами с учётом приватности точных координат.
- **ИИ-рыболов:** советы и анализ рыболовной ситуации; новая модель Yandex/DeepSeek пока проходит отдельную STAGING-приёмку.

Часть перечисленного реализована в коде, часть находится на этапе интеграции или тестирования. Возможности Атласа, гидов и платных сервисов не следует считать готовыми без соответствующих проверок.

## Дизайн

Утверждённый дизайн: **v0.6.0-admin-rc.1**. Сохраняются фирменная стилистика, навигация **«Лента · Комьюнити · + · Выезды · Чат»** и две темы:

- **Matte Black** — оформление по умолчанию: графит и электролайм.
- **Electric Blue** — необязательный синий вариант с лаймом и баклажановыми акцентами.

Не возвращать прежние макеты и не менять утверждённый визуал без решения владельца. Источник: [design lock](docs/ZAPRUDA_DESIGN_LOCK_v0.6.0-admin-rc.1.md) и [текущий продуктовый контекст](docs/ZAPRUDA_CURRENT_SOURCE_OF_TRUTH.md).

## Технологии

React, TypeScript, TanStack Start/Router, Vite, Tailwind CSS, Supabase (Auth, PostgreSQL, RLS, Realtime, Edge Functions), Bun/Vitest и Node/Nitro. В проекте используется `bun.lock`.

## Локальный запуск разработчика

Использовать **только отдельный STAGING Supabase**, не production. Скопировать `.env.example` в локальный `.env` и заполнить публичные параметры:

```dotenv
VITE_SUPABASE_URL=https://<staging-project>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=<staging-publishable-key>
```

```bash
bun install --frozen-lockfile
bun run dev
```

Для проверки:

```bash
bun run typecheck
bun run lint
bun run test
bun run build
```

**Не помещать секретные или service-role ключи в `VITE_*`**, поскольку они попадают в клиентскую сборку.

## Релиз и безопасность

Изменения сначала проходят через проверяемую интеграционную ветку и изолированный STAGING. Не обновлять автоматически `main`, production Supabase, DNS, публичный домен и платежи. Не переносить в production тестовые данные и STAGING-only SQL.

Текущие критерии приёмки и открытые блокеры — в [release readiness](docs/ZAPRUDA_V075_SPOT_RELEASE_READINESS.md). Полное прохождение тестов кода ещё не подтверждает, что пользователь может безопасно войти и пользоваться опубликованным приложением.
