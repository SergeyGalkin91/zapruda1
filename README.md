# ZAPRUDA COMMUNITY

**ZAPRUDA COMMUNITY** — русскоязычная mobile-first платформа для **всех направлений рыбалки**, а не только спиннинга. Здесь рыболовы делятся уловами, находят друзей и напарников, вступают в клубы, организуют совместные выезды и Street Fishing, сохраняют личные рыболовные места и получают персональные рекомендации. Отдельное направление — проверенные рыболовные гиды, в том числе услуги с современной электроникой и **Panoptix / LiveScope**.

**Текущий продукт:** `v0.7.0-alpha` (разработка и проверка, не утверждённый production-релиз). **Рабочая ветка:** `release/v0.7.0-alpha`. Ветка `main` не является источником актуальной Alpha-версии.

## Продуктовая структура

Целевая навигация из пяти разделов (часть изменений находится в отдельных Draft PR и **ещё не внедрена** в базовую Alpha):

1. **СПОТ** (`/spot`) — «Покажи свой улов», «Найти клуб», «Собрать вечерний стрит». Публичная лента уловов остаётся по `/`; создание отчёта — `/reports/new`. Новый хаб СПОТ не следует путать с геочатом ZAPRUDA SPOT (`/chat`).
2. **Комьюнити** (`/communities`) — найти напарника для общения 1:1, найти или создать клуб, найти рыболовного гида. Планируемая стоимость создания клуба — **500 ₽**, лимит — **до 15 участников**; серверная реализация и платежи требуют проверки.
3. **Выйти на воду** (`/assistant`) — персональный ИИ-помощник **BETA**: район/тип воды, снасти, целевая рыба, тактика. Чужие точные координаты не раскрываются.
4. **Сообщения** (`/messages`) — личное общение и развитие реакций.
5. **Профиль** (`/profile`) — анкета рыболова, способы ловли, любимые водоёмы, снасти, аватар и настройки приватности.

### Услуги гидов и развитие платформы

Гид подаёт бесплатную заявку на проверку. Целевой сценарий: каталог услуг, календарь и бронирование, общение по заказу, оплата внутри платформы, подтверждение поездки, отзывы только по состоявшимся бронированиям. **Целевая комиссия ZAPRUDA — 10% с оплаченного заказа**; фактический платёжный процесс пока не следует считать готовым. Услуги могут включать береговую и лодочную рыбалку, обучение, подбор техники, современный эхолот и Panoptix / LiveScope при наличии оборудования у гида.

Соревнования и спонсорские механики — более поздний этап, не обязательный для Alpha.

## Приватность рыболовных мест

**Точные координаты личных спотов приватны по умолчанию.** Публичный отчёт не должен выдавать чужие точные GPS-координаты. В будущем обмен конкретной точкой — только по явному действию владельца с понятной аудиторией доступа. Не добавляйте прямую публикацию приватных точек в общедоступные отчёты и чаты.

## Статус реализации

В кодовой базе Alpha существуют маршруты отчётов, профиля, сообществ, чатов, гидов и ИИ-помощника, а также административные интерфейсы. **Наличие экранов и исходного кода не подтверждает end-to-end работу.** Новый хаб СПОТ и обновление навигации, реакции в ЛС и новые клубные/гидовые сценарии ведутся отдельными PR. Не выдавайте планы за готовый функционал.

**Главный технический блокер:** отдельный Supabase STAGING пока не повторяет необходимую схему для проверки клубов, личных сообщений и гидов. Production не используется для Alpha-тестов и не изменяется без явного отдельного согласования.

## Технологии

React 19, TypeScript, TanStack Start / Router, Vite, Tailwind CSS, Supabase (PostgreSQL, Auth, RLS, Realtime), Bun, Docker и Netlify Preview.

### Локальная разработка

Используйте Bun и сохранённый `bun.lock`; не смешивайте менеджеры пакетов при обновлении зависимостей. Создайте локальный `.env` по `.env.example` и укажите **только публичные** параметры отдельного STAGING:

```dotenv
VITE_SUPABASE_URL=https://<your-staging-project>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=<public-publishable-key>
```

```bash
bun install
bun run dev
bun run build
bun run test
```

Не коммитьте `.env`; никогда не передавайте `service_role`, secret key и пароли БД в переменные `VITE_*` или клиентский код.

Docker STAGING: [инструкция](docs/ZAPRUDA_V070_DOCKER_STAGING.md).

## Дизайн

Утверждённый визуальный язык: почти чёрный графит, лайм **`#D7FF35`**, приглушённый лавандовый акцент, компактный mobile-first UI и живые, но доступные hover/pressed/focus-состояния. Историческое название [дизайн-фиксации](docs/ZAPRUDA_DESIGN_LOCK_v0.6.0-admin-rc.1.md) **не обозначает текущую версию приложения**. Не возвращайте прежний интерфейс без согласования.

## Правила разработки и релиза

- Разработка идёт от `release/v0.7.0-alpha` через небольшие **Draft PR**. `main` и production не изменяются автоматически.
- Сначала проверяйте существующий код и актуальные продуктовые решения. Ранние экспериментальные чаты, архивные PR и старые README не являются действующим техническим заданием.
- Перед слиянием: типы, сборка, тесты, RLS/GRANT, реальные сценарии авторизации двумя пользователями и проверка мобильного интерфейса.
- База STAGING и миграции должны проверяться отдельно; не копируйте пользовательские данные production и не восстанавливайте старые сущности только потому, что они были в ранней версии.

См. [аудит устаревших PR](docs/ZAPRUDA_LEGACY_CLEANUP_AUDIT_20261102.md) (документ пока в отдельном Draft PR), [продуктовую архитектуру СПОТ / Комьюнити / Гиды](docs/ZAPRUDA_PRODUCT_ARCHITECTURE_SPOT_COMMUNITY_GUIDES.md) (также в отдельном PR).
