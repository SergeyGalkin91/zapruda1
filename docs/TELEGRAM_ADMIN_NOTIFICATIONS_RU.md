# ZAPRUDA — обращения в администраторский Telegram-чат

Реализовано:
- Страница приложения `/feedback` с формами «Предложить улучшение» и «Сотрудничество».
- Авторизованный приём заявок через Edge Function `submit-community-feedback`.
- Сохранение приватных заявок в `public.community_feedback` (RLS), ограничение 3 обращения/час и 10/сутки на пользователя.
- После сохранения функция пытается отправить сообщение в **закрытый чат администрации** Telegram через Bot API.
- Если Telegram недоступен или секреты не заданы, обращение **всё равно сохраняется**; функция возвращает `notification: pending`. Доставка задним числом и изменение `telegram_status` пока не реализованы, поэтому не обещать повторную автоматическую доставку.
- Никакого бота/токена в исходниках или браузере.

## Что владелец должен сделать в Telegram
1. Открыть `@BotFather` в Telegram и выбрать `/newbot`. Важно проверить официальный аккаунт.
2. Создать новый бот проекта, например `Zapruda Community Admin Bot`; **токен не отправлять в чат ChatGPT, GitHub или публичную группу**.
3. Создать отдельную **приватную группу** администрации (можно назвать `ZAPRUDA | Администраторы`) и добавить туда бота с разрешением отправлять сообщения. Не использовать публичную группу `@ZAPRUDACOMMUNITY` для заявок с личными контактами.
4. Узнать числовой `chat_id` закрытой группы (обычно начинается на `-100`). Это можно сделать через служебное сообщение в группе и Telegram Bot API `getUpdates` в приватном браузере или локально; не выкладывать токен в третьи сервисы. Возможен специальный админ-бот-помощник, но минимизировать доступ сторонних ботов.
5. В Supabase Dashboard → Project → Edge Functions → Secrets создать два секрета:
   - `ZAPRUDA_TELEGRAM_BOT_TOKEN` = токен BotFather
   - `ZAPRUDA_TELEGRAM_ADMIN_CHAT_ID` = числовой id приватной группы
6. Открыть приложение `/feedback`, войти, отправить тестовую заявку. Убедиться, что в базе сохранилась запись и закрытая группа получила уведомление.

Если один из секретов отсутствует, заявки продолжат сохраняться в Supabase, а Telegram не получит уведомление.

## Безопасность
- Не передавать пароль, токен Bot API, service_role, секретный ключ Supabase или URL с токеном в чаты и документы.
- Пользователь видит собственные обращения, но другие пользователи — нет. Поле `status` нельзя редактировать из браузера.
- Для административной панели потребуются отдельные серверные роли с явно назначенными разрешениями и обработка/повторная отправка pending-записей.
- После подключения обязательно проверить полную цепочку с реальным пользователем и администратором, а также rate limit.
- Прямого доступа к администрированию Telegram-группы из этого чата нет.
