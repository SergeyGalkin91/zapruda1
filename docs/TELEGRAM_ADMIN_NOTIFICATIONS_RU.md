# ZAPRUDA — реальные Telegram-уведомления администратору

## Реализовано и проверено
- Действующий экран `/feedback`: «Предложить улучшение», «Сотрудничество», «Сообщить об ошибке».
- Действующая Supabase Edge Function `submit-community-request`, требует авторизацию и проверяет пользователя.
- Формы создают записи в `public.community_requests`. У автора есть доступ только к собственным обращениям; запись на стороне сервера.
- Если Telegram настроен, функция отправляет сообщение в закрытый чат через Telegram Bot API и отмечает результат `telegram_status = sent/failed`.
- При сбое Telegram исходное обращение остаётся в базе с `telegram_status = failed/pending`. **Автоматического повторного отправления пока нет**.
- Функция существует в Supabase и сохранена в GitHub: `supabase/functions/submit-community-request/index.ts`.
- Публичный канал пользователей: https://t.me/ZAPRUDACOMMUNITY. Нельзя направлять туда заявки с контактами и жалобы.

## Как завершить подключение (только владелец Telegram)
1. В Telegram открыть официальный `@BotFather`, отправить `/newbot`, создать бота с уникальным username, например `ZaprudaAdminNotifyBot`, если свободен.
2. Создать **приватную** группу «ZAPRUDA | Администрация» (отдельно от публичного канала) и добавить в неё бота с правом отправлять сообщения.
3. Получить числовой идентификатор приватной группы (`chat_id`, обычно начинается с `-100`). Можно использовать сообщение в группе и API `getUpdates` через локальный браузер/скрипт, не передавая токен третьим лицам. Если у бота установлен webhook, `getUpdates` может быть недоступен.
4. В Supabase Dashboard: https://supabase.com/dashboard/project/sonvniuwtvzzyuglscah/functions/secrets создать:
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather;
   - `TELEGRAM_ADMIN_CHAT_ID` — числовой ID приватной группы.
5. Открыть `/feedback` в запущенном ZAPRUDA, войти, отправить проверочное обращение. Оно должно появиться в приватном чате. Проверить `telegram_status` и `telegram_sent_at` в Supabase `community_requests`.

Не отправлять токены, пароли и секретные ключи в ChatGPT, GitHub, Telegram-группу или публичные сообщения. Токен должен храниться только в секрете Supabase.

## Обработка обращений
- Вид обращения: `improvement`, `cooperation` либо `bug`.
- После принятия обращения добавляется информация о теме, описании, контакте (если указан), UUID заявки.
- Нужны дополнительные этапы до полноценного production: автоматический retry по статусам `pending/failed` с защитой от дубликатов, панель модератора, тест отправки с двумя аккаунтами, политика хранения контактов.
- Никаких публикаций в Telegram от имени владельца не делается без явного подтверждения.

## Фактический статус на 29.10.2026
Код и база готовы к испытанию. Бот и закрытый чат в Telegram **не созданы/не подтверждены как подключённые этим помощником**, секреты не подтверждены. Уведомления не считаются работающими до первого успешного теста.
