# ZAPRUDA / ON SPOT — Local Crew
**Дата:** 05.11.2026. **Источник:** прямое предложение владельца и подтверждение: «зафиксируй это срочно, чтобы не забыть эту фичу, считаю он и правда хороша».
**Статус:** OWNER-APPROVED IDEA / PRODUCT BACKLOG — **NOT IMPLEMENTED; NOT PILOT P0; NOT RELEASE GATE**.
Не путать с существующей функцией SPOT (локация/трофей/модерация) или с технической онлайн-активностью в обычных чатах.

## Зачем
Помочь рыбакам, особенно STREET FISHING, **находить своих поблизости**, вступать в локальный чат, договариваться о совместной рыбалке и по взаимному согласию публиковать совместные фото/отчёты. Это социальный слой поверх существующих **SPOT, Chat, STREET и СХОДОК**. Обычный просмотр карты НЕ означает согласие на раскрытие присутствия.

## Предлагаемый UX (сохранить все варианты)
1. В SPOT/карте появится отдельный вход **«ON SPOT / Рыбаки рядом»**. Не менять существующую базовую навигацию `Лента / Комьюнити / + / Выезды / Чат` без отдельного решения.
2. Владелец идеи предложил **радиус около 1 км (±)**: показывать доступный **локальный чат района** и, при отдельном opt-in, список добровольно доступных для знакомства рыбаков. Радиус — предварительная продуктовая гипотеза, **не точность публичных координат** и не сигнал «на этой точке точно рыбачат».
3. Режимы участия:
   - **Невидимый (default):** можно смотреть обычную карту/споты, не отмечаться в ON SPOT и не получать локальные приглашения.
   - **Локальный чат:** сознательное вступление в районный чат без публикации профиля как присутствующего на карте.
   - **Открыт к знакомству:** явное добровольное включение списка доступных рыбаков без точных GPS-пинов; отдельный переключатель локальных приглашений/уведомлений.
4. Общий запрос вроде **«Кто сейчас рядом и хочет порыбачить вместе?»** отправляется **не автоматически всем в километре**, а только согласившимся на такие приглашения участникам подходящего района/чата; лимиты частоты, блокировка и жалобы.
5. Можно отправить **взаимное приглашение встретиться**, перейти в личный диалог после согласия, подписаться/подружиться, затем добавить **совместное фото или отчёт** только при согласии изображённых участников. Никакой автоматической дружбы или фотографирования.
6. Добровольный чекин имеет ограниченный TTL (для концепта — ~2 часа, требует UX-валидации), мгновенное выключение, возможность завершить сессию; отключение геолокации не должно оставлять «призрак присутствия».

## Приватность и anti-abuse — обязательные границы до реализации
- **Никакого пассивного GPS-трекинга, автозаписи присутствия при просмотре карты, точных пользовательских координат, истории маршрутов и принудительных пушей.**
- Серверная проверка ограниченной территориальной принадлежности/приближённого радиуса только при явном согласии; наружу не отдавать точку, время/трассу движения, точный радиус до человека. Обсудить устойчивые зоны или достаточно крупные ячейки для уменьшения deanonymization через повторяющиеся поиски/пограничные запросы.
- Не показывать число/аватары участников в малых группах без адекватной защиты от раскрытия: подумать о минимальных порогах, размытых счетчиках, приватных/закрытых спотах, задержках/ограничениях обновлений; GPS/EXIF фото очищать.
- Раздельные согласия на локальный чат, статус присутствия, уведомления, личные запросы и совместные фотографии; возможность скрыться, заблокировать, пожаловаться, отозвать согласие.
- Настройки видимости, rate limits, антиспам, модерация, TTL и удаление устаревших сессий на сервере. Не хранить/логировать точные координаты в аналитике без подтверждённого legal/privacy design.
- Прототип **не должен выводить настоящие личности/точки** без согласия и проверок. При недостаточном количестве добровольцев показывать пустое состояние, не выдумывать «3–4 рыбака рядом».

## Фазы и проверки (proposal; не считать выполненными)
- **Исследование / дизайн:** проверить, нужен ли локальный чат в радиусе 1 км, не пересекается ли с городскими чатами/СХОДКАМИ, нарисовать Premium UI в утверждённой ZAPRUDA-айдентике, определить приватные зоны и правила.
- **MVP:** локальный чат по **крупной зоне** с ручным opt-in; приглашения внутри чата без точного присутствия; по реальным добровольным тестерам.
- **Фаза 2:** ограниченный по времени статус «открыт к знакомству», согласованные запросы, отдельные уведомления и взаимные подписки.
- **Фаза 3:** совместные фото/отчёты с согласием и privacy-guard; более тонкая зональность только после отдельной privacy/abuse приёмки.
- **Acceptance:** корректный opt-in/opt-out, 0 координат в публичном API, отсутствие утечек через поиск/маркеры/повторные запросы, rate limits, блокировка, TTL и no-ghost, проверка минимум двух реальных STAGING тестовых аккаунтов, 320/390 UX, журнал отзыва согласия, STAGING E2E.
