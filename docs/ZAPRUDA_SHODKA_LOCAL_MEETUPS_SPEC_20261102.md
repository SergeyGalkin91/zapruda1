# СХОДКА — локальные мини-встречи рыболовов | ZAPRUDA COMMUNITY v0.7.0-alpha

**Статус:** новая продуктовая спецификация, НЕ реализовано. Ниже разделены утверждённые владельцем требования и уточнения проекта.

## Утверждено владельцем (2026-11-02)

- Отдельный раздел поиска **«СХОДКИ»** внутри Комьюнити, не путать с платным Клубом (максимум 15).
- Рыболов создаёт **объявление** для поиска компании.
- Второй рыболов откликается; после принятия заявки организатором создаётся **«СХОДКА»**, где участники отдельно договариваются о конкретном месте и времени.
- В одной СХОДКЕ **не более 3 человек**, включая организатора.
- Геопоиск строго по выбранной локации: **страна → регион → город**. Например, объявление для «Россия / Нижегородская область / Нижний Новгород» видно при выборе именно этой локации, а не всем пользователям страны.

## Предлагаемый UX (требует приемки)

Комьюнити → СХОДКИ → «Найти сходку» / «Создать объявление» / «Мои сходки». Карточка объявления: город, вид рыбалки, примерный день, число свободных мест, ник организатора, кнопка «Откликнуться». Без точных GPS и приватных контактов.

Статусы объявления: `open`, `full`, `cancelled`, `closed`. Статусы отклика: `pending`, `accepted`, `declined`, `withdrawn`. СХОДКА создаётся один раз при первом принятом отклике. Третий человек может войти только после принятия второго отклика; при 3 участниках набор закрывается. Точный адрес и время доступны только в закрытом чате участников после принятия.

Предлагается не смешивать СХОДКИ с `partner_trips` (поездки с транспортом, финансовыми договорённостями и услугами гидов), `social_groups` (клубы до 15 человек) и `social_threads` (личные 1:1 переписки). Возможно повторное использование интерфейсных элементов, но не переименование существующих финансовых сущностей.

## Требования безопасности к реализации

1. Серверная нормализованная география (код страны/региона/города), фильтр **не только в UI**: запрос объявлений ограничен выбранным городом. Город не определяется автоматически из точных координат и не раскрывает место рыбалки. У клиента должен быть явный выбор локации.
2. Транзакционные операции принятия отклика: **блокировка объявления или advisory lock**, подсчёт принятых участников под блокировкой. Максимум 3 включая автора; отдельные одновременно принятые отклики не должны переполнить лимит.
3. Создание приватной встречи атомарно при первом подтверждении; уникальный ключ `announcement_id` предотвращает дубли.
4. RLS: объявление для выбранной локации видимо по правилам регионального поиска; приватные сообщения, точная точка и время доступны исключительно принятым участникам; отклик отправляет только авторизованный пользователь, организатор не откликается на себя.
5. Не переводить кандидата в участники и не отправлять уведомление до подтверждения транзакции. Если заявка отклонена/отменена, права на закрытый чат не выдаются. Удалённый участник теряет доступ; исключения требуют явного UX-решения.
6. Тесты с тремя реальными JWT и четвёртым посторонним: локальность, невозможность просмотра чужого приватного чата, отказ при 4-м участнике, конкурентное принятие, повторные запросы, смена города и отсутствие GPS в публичных полях.
7. **Платежей здесь нет**: 500 ₽ относится к созданию клуба, не к СХОДКЕ.

## План внедрения

- Отдельный Draft PR от `release/v0.7.0-alpha` после ревью схемы. Создать STAGING-only миграцию и RLS, проверить привилегии.
- Отдельный UI маршрут `/meetups` или `/shodki` (название маршрута техническое, требуется единообразие) и точка входа из «Комьюнити». 
- Не переиспользовать неподтверждённые SQL таблицы и не менять production. Не считать готовым до тестов двух/трёх участников, отказа четвёртому, города и приватного чата.

## Открытые вопросы для UX, не блокирующие спецификацию

- Как показывать объявления «рядом»: строго один город по умолчанию, расширение на область — только отдельным явным переключателем.
- Продолжает ли СХОДКА существовать после выхода второго участника (предлагается сохранить с возможностью нового отклика).
- Когда фиксируется конкретный день/время, какие уведомления получает третий приглашённый.


## УТВЕРЖДЕНО ВЛАДЕЛЬЦЕМ — обязательная функция релиза v0.7.1 (2026-11-02)

Статус этой функции: **APPROVED / MUST HAVE for v0.7.1**. Ранее она описывалась как новая концепция для v0.7.0-alpha; теперь целевой выпуск — **v0.7.1**, без утверждения готовности реализации. Ветки Alpha и production не меняются автоматически.

### Обязательные пользовательские сценарии
1. В разделе Комьюнити есть отдельный вход **«СХОДКИ»** и отдельная страница локальных объявлений.
2. Пользователь вручную выбирает **страну → регион → город**. Публичная выдача соответствует именно выбранному городу; пример: Россия / Нижегородская область / Нижний Новгород. Местоположение пользователя не определяется по точному GPS без явного согласия.
3. Можно создать настоящее объявление и откликнуться на него; интерфейс работает на реальных данных Supabase и не показывает фиктивные объявления как настоящие.
4. При принятии первого отклика организатором атомарно создаётся приватная **СХОДКА** с чатом для обсуждения конкретного места и времени.
5. СХОДКА ограничена **3 участниками включая организатора**; третий человек может войти после отдельного принятия, четвёртый не может быть принят даже при конкурентных запросах.
6. Закрытый чат и точные место/время доступны только принятым участникам. Публичная карточка не содержит точных GPS-координат и личных контактов.
7. СХОДКА полностью независима от **КЛУБА** (500 ₽ за создание и до 15 участников) и от платных поездок/гидов.

### Утверждённый визуальный ориентир
Владелец утвердил концепцию словами «ну да, примерно так». Ориентир: мобильный тёмный/графитовый экран, лайм **#D7FF35**, лавандовые вторичные акценты, крупный заголовок **«СХОДКИ»**, карточка **«ВЫБРАННАЯ ЛОКАЦИЯ»**, кнопки **«+ Создать объявление»** и **«Мои сходки»**, карточки объявлений со счётчиком **1/3**, **2/3**, **3/3** и кнопкой **«Откликнуться»**. Сохранять композицию, но адаптировать размеры к реальным телефонам; не воспроизводить фиктивные карточки в production. Визуальный образец обсуждался в чате 2026-11-02 и должен быть добавлен в репозиторий отдельно, если понадобится бинарный asset.
