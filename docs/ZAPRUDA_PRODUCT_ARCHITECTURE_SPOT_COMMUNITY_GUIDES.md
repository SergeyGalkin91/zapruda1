# ZAPRUDA COMMUNITY — продуктово-техническая архитектура

**Статус:** предварительный проект (design), не утверждённая реализация  
**Версия приложения:** v0.7.0-alpha  
**Дата:** 2026-11-02  
**Ветка для внедрения:** только от `release/v0.7.0-alpha`, отдельные Draft PR  
**Запрещено без отдельного решения:** main, production Supabase, ломка design lock

Документ фиксирует согласованную с владельцем логику:

- хаб **СПОТ**;
- **Выйти на воду** (ИИ BETA);
- **Комьюнити**: напарник, клуб, гид;
- **вечерний стрит**;
- личные сообщения и реакции;
- маркетплейс гидов с комиссией 10%;
- соревнования — только в будущем.

Код в рамках этого документа не считается выполненным: это чертёж для ChatGPT и Grok.

---

## 1. Цели

1. Собрать разрозненные действия («лента», «отчёт», «выезды») в понятный вход **СПОТ**.
2. Сделать **Комьюнити** местом людей: напарник, клуб, гид — без смешения с гео-чатом.
3. Встроить **гидов** как поток с оплатой и комиссией, а не как «визитку».
4. Сохранить **приватность точных координат** и текущий design lock.
5. Не переписывать работающие маршруты: новые хабы **ведут** на существующие URL.

## 4. Комьюнити — три направления

### 4.1. Найти напарника

**Цель:** договориться о совместной рыбалке и открыть **приватный чат на двоих**.

Поток:

1. Пользователь заполняет короткий запрос (район, дата, стиль ловли) *или* выбирает анкету.
2. Отправляет приглашение / принимает входящее.
3. После accept создаётся или открывается `social_threads` (модель 1:1 уже в продукте).
4. Переписка в `/messages`.

**Не смешивать** с публичным `/chat` и с платным клубом.

### 4.2. Создать клуб / команду

| Параметр | Значение |
|----------|----------|
| Цена создания | 500 ₽ |
| Участников | максимум 15 (серверный лимит) |
| Оплата | только через ZAPRUDA (существующий paid club flow) |
| После оплаты | пространство общения + организация рыбалок |

Серверно: запрет 16-го участника (триггер/проверка в RPC, не только UI).

### 4.3. Найти гида (маркетплейс)

См. раздел 6.

Табы `/communities`:

```
[ Напарник ] [ Клубы ] [ Гиды ]
```

Контент табов — обёртка над текущими компонентами (`SocialGroups`, guides, partners), без второй «параллельной» соцсети.

## 5. Вечерний стрит

**Смысл:** найти небольшую компанию на рыбалку в определённой местности на конкретное время.

### Поля сбора

- Район / водоём (текст или **приблизительные** координаты).
- Дата и время.
- Число мест (рекомендуемый диапазон 2–6).
- Комментарий организатора.

### Жизненный цикл

`draft → open → full | cancelled → done`

Отклик → accept/decline → при accept участник видит уточнения по встрече согласно правилам приватности.

### Приватность

Точные GPS **не публикуются** в открытой ленте.  
Уточнение места — организатору и принятым участникам, по тем же принципам, что private locations отчётов.

### Связь с `/street`

- `/street` — личный трекер сессии (как сейчас).
- `/street/gather` — социальный сбор компании.
- После рыбалки опционально: «оформить улов» → `/reports/new`.

## 6. Гиды и комиссия 10%

### 6.1. Бизнес-правила

| Правило | Описание |
|---------|----------|
| Вход гида | Бесплатная анкета |
| Комиссия | 10% только с **оплаченной** и учитываемой сделки |
| Гид получает | 90% (до эквайринга, налогов, возвратов) |
| Сделка | Только статус paid/completed в ZAPRUDA |
| Отзыв | Только после завершённой поездки |
| Рейтинг | Считается по подтверждённым поездкам |

Пример: услуга 20 000 ₽ → платформа 2 000 ₽ → гид 18 000 ₽.

### 6.2. Воронка клиента

1. Каталог: регион, вид ловли, цена, рейтинг.
2. Карточка гида: описание, фото, календарь, число завершённых выездов.
3. Запрос бронирования → **внутренний чат заказа**.
4. До оплаты: без телефона и внешних мессенджеров в явном виде (фильтр/предупреждения).
5. Оплата в приложении → контакты и место встречи.
6. Завершение → отзыв.

### 6.3. Воронка гида

Обычная регистрация → «Стать гидом» → заявка (регион, опыт, услуги, цены, фото, документы) → модерация админом → статус verified → кабинет заказов.

### 6.4. Защита комиссии (реалистичная)

Полностью запретить договорённость вне приложения нельзя. Делаем сделку внутри выгоднее и безопаснее:

1. Юридически и продуктово сделка = paid booking.
2. Контакты после оплаты (`contacts_unlocked_at`).
3. Отзывы и рейтинг только с completed.
4. Выдача в поиске и бейдж «проверенный» завязаны на дисциплину и completed.
5. Правила: запрет навязчивого увода в мессенджеры до оплаты; жалобы; предупреждения/ограничения выдачи.
6. Не читаем все личные переписки и не обещаем 100% контроль.

Оплата в РФ: ориентир ЮKassa (безопасная сделка / комиссия площадки) — отдельное юридическое и договорное решение.

### 6.5. Данные (ориентир)

Использовать существующие `guide_profiles`, заявки, `guide_booking_inquiries` / finance.

Добавлять только при пробелах (STAGING, отдельные PR):

- `guide_reviews` с FK на completed booking;
- поля комиссии: `amount_rub`, `platform_fee_rub`, `guide_net_rub`;
- `contacts_unlocked_at` / статус заказа;
- при необходимости `thread_kind` для order-chat.

## 7. Выйти на воду (ИИ BETA)

- Маршрут: `/assistant` (существующий).
- В навигации — отдельный пункт, не внутри СПОТ.
- Ответ: район/тип воды (без чужих точных GPS), снасти, объект, тактика.
- Лимит запросов в сутки (BETA), только авторизованные.
- Логи уже могут писаться в существующую модель assistant logs — не дублировать.

## 8. Личные сообщения

Доработка существующего `/messages`:

- реакции на сообщения (по аналогии с реакциями в гео-чате, отдельная таблица или переиспользование паттерна);
- стабильный realtime без дублей подписок;
- пустые состояния, ошибки сети, повтор отправки.

Не строить третий мессенджер рядом с `/chat` и order-chat: разные **типы** тредов в одной системе предпочтительнее.

## 10. Модель данных — принципы

1. Максимум существующих таблиц и RLS.
2. Новые сущности — только под доказанный пробел (gathering, review constraints).
3. Лимит клуба 15 — на сервере.
4. Комиссия и net — на сервере при переходе статуса оплаты, не только в UI.
5. Точные координаты — private by default (уже принятое security-решение).
6. Миграции сначала STAGING (`yudtbifopfnjtjanaqrd`), production — отдельным решением владельца.

## 11. Этапы внедрения

### Этап 0 — документ (этот файл)

Согласование IA и бизнес-правил. Без изменения runtime.

### Этап 1 — IA и хабы (UI)

- Маршрут `/spot` + три перехода.
- Shell: СПОТ, Комьюнити, Выйти на воду, Сообщения, Профиль.
- `/communities` — табы-обёртка (напарник / клубы / гиды) над текущим функционалом.
- Без новых таблиц.

**Приёмка:** с телефона за ≤3 тапа до улова, клубов, стрита (заглушка или partners), гидов, ИИ.

### Этап 2 — напарник и ЛС

- Поток «найти напарника» → accept → тред 1:1.
- Реакции в личных сообщениях.
- QA двух аккаунтов на STAGING.

### Этап 3 — клуб 500 ₽ и лимит 15

- Серверный лимит участников.
- Оплата создания только через штатный paid flow.
- Админ видит заявки.

### Этап 4 — вечерний стрит

- `street_gatherings` (+ members) на STAGING.
- Экран сбора, отклики, приватность места.
- Связь «завершил → отчёт».

### Этап 5 — гиды и 10%

- Каталог, бронь, статусы, order-chat.
- Комиссия, net, отзывы после completed.
- Антиобходные правила (фильтры, contacts unlock).
- Тестовые платежи на STAGING.

### Этап 6 — соревнования

Только после спонсоров и отдельного ТЗ.

Каждый этап: ветка `grok/...` или согласованная с ChatGPT, **Draft PR**, не merge в main самостоятельно.
