# SPOT: отзыв подтверждения и повторные решения

Дата проверки: 2026-11-04 (Москва). Изменения предназначены только для STAGING.

## Исправление

- Уполномоченный модератор с подтверждённой почтой может отозвать чужой подтверждённый улов с обязательной причиной 10–500 символов. Назначение модераторов не меняется.
- Отзыв пересчитывает все затронутые титулы по действующим проверенным уловам. Учитываются дисциплина, метод, область, вид/сезон, разрешённый спот, доступное одобренное фото, UL-снасть и проверка благополучия MICRO. При отсутствии подходящего предшественника титул снимается.
- Весовые номинации сравнивают вес; LENGTH KING и MICRO KING — длину. Равный действующий рекорд сохраняется.
- Подтверждение и отзыв берут блокировки категорий в одном порядке. Повторное решение не дублирует историю и уведомления. Причина отзыва остаётся в закрытой схеме.
- Закрытые уловы, фото и уведомления очищаются при выходе/смене аккаунта; поздние ответы старого аккаунта игнорируются. Перед отправкой проверяется принадлежность токена. Обновление токена того же пользователя сохраняет черновик.
- Edge Function не возвращает пользователю внутренние сообщения SQL.

## Проверки и границы

Локально прошли 329 тестов в 26 файлах, TypeScript, ESLint (0 ошибок, 6 прежних предупреждений) и production build. Включены 7 проверок правил SQL на PGlite и 4 проверки границ сессии компонента.

Workflow `spot-postgres.yml` запускает настоящий отдельный PostgreSQL 17 и независимые параллельные SQL-соединения: конкурирующие подтверждения, отзыв одновременно с подтверждением, восстановление предшественников, снятие последнего титула, повторные запросы и уведомления по дисциплине. Он отказывается обращаться к hosted БД и использует только искусственные SQL-идентичности в одноразовой базе CI. Его результат следует читать в GitHub Actions на SHA данного изменения. Это проверка транзакций, а не E2E с настоящими JWT.

В hosted STAGING до применения этой дельты: 0 модераторов, 0 разрешённых спотов, 0 уловов и 0 действующих титулов. Эти сущности данным изменением не создаются. Настоящая положительная проверка KING требует отдельно разрешённого модератора, юридически проверенного спота и подлинного материала.

SQL bootstrap из `supabase/tests/unit/` запрещено применять к STAGING/production. В hosted STAGING применяется только новая дельта `supabase/staging/v075_spot_revocation_recalculation.sql` после сверки фактической схемы и прохождения CI. Production не изменяется.
